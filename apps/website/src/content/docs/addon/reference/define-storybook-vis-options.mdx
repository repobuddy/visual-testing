A helper function to define options for the Storybook Visual Testing addon.
It returns the options you pass in, which gives you type checking and completion.

```ts
// .storybook/main.ts
import { defineMain } from '@storybook/your-framework'
import { defineStorybookVisOptions } from 'storybook-addon-vis/node'

export default defineMain({
	addons: [
		{
			name: 'storybook-addon-vis',
			options: defineStorybookVisOptions({
				visProjects: [
					{
						snapshotRootDir: () => '__vis__/linux',
					},
					{
						snapshotRootDir: () => '__vis__/local',
					},
				],
			}),
		},
	],
})
```

## Function signature

```ts
function defineStorybookVisOptions(options: StorybookVisOptions): StorybookVisOptions
```

## Options

### `visProjects`

Configure one or more visual testing projects.
Each project can have its own snapshot storage settings.

### `snapshotRootDir`

Where snapshots are stored. It resolves to the same folder as the same value given to `vis()` or `storybookVis()` in Vitest, so you can copy the value from your Vitest config. It can be:

- `undefined`, which uses the default: `__vis__/<platform>` in CI and `__vis__/local` elsewhere.
- A path string. As in the plugin, the addon adds `<platform>` in CI and `local` elsewhere: `'__vis__'` reads `__vis__/linux` on Linux CI and `__vis__/local` on your machine.
- A function. Its return value is used as is. It receives the same fields as in the plugin:
  - `ci`: whether the code runs in a CI environment.
  - `platform`: the platform string (for example `linux`, `darwin`, `win32`).
  - `rootDir`: `'__vis__'`.
  - `projectName`, `browserName`, `providerName`: Storybook does not run a Vitest project or a browser, so these are the values you set on the same `visProjects` entry, or `undefined`.
  - `screenshotFailures`, `screenshotDirectory`: always `undefined`.

To show a fixed folder, such as the Linux CI baselines while you work on your machine, return it from a function: `snapshotRootDir: () => '__vis__/linux'`.

### `projectName`, `browserName`, `providerName`

Values passed to a `snapshotRootDir` function.
Set them when your Vitest `snapshotRootDir` function uses them, and add one `visProjects` entry per Vitest project or browser instance:

```ts
const snapshotRootDir = ({ ci, platform, projectName }: { ci: boolean; platform: string; projectName?: string | undefined }) =>
	`__vis__/${ci ? platform : 'local'}/${projectName}`

defineStorybookVisOptions({
	visProjects: [
		{ projectName: 'HD', snapshotRootDir },
		{ projectName: 'SVGA', snapshotRootDir },
	],
})
```

### `snapshotSubpath`

Transform the default snapshot subdirectory path to match your project structure.
It receives `{ subpath: string }` and returns the transformed subpath.
`subpath` is the story file path relative to the project root, such as `src/button.stories.tsx`: the import path Storybook reports, without the leading `./`. It is the same value the plugin passes for the same file, so one function gives the same folder in both.
The default removes a leading common folder (`src`, `source`, `test`, `tests`, `lib`, `js` or `ts`).

### `shortenLongSnapshotPaths`

Shortens snapshot paths that would be too long, the same way the `shortenLongSnapshotPaths` option of the [Vitest plugin](/visual-testing/plugin/reference/config/vis/#shortenlongsnapshotpaths) does.
It defaults to `false`.

## Examples

### Store snapshots in a custom directory

```ts
import { defineStorybookVisOptions } from 'storybook-addon-vis/node'

const options = defineStorybookVisOptions({
	visProjects: [
		{
			snapshotRootDir: '__vis__/snapshots',
		},
	],
})
```

### Use different directories for CI and local development

```ts
import { defineStorybookVisOptions } from 'storybook-addon-vis/node'

const options = defineStorybookVisOptions({
	visProjects: [
		{
			snapshotRootDir: ({ ci, platform }) => {
				if (ci) {
					return `__vis__/ci/${platform}`
				}
				return '__vis__/local'
			},
		},
	],
})
```

### Customize the snapshot subdirectory structure

The default already drops a leading `src/`.
To drop another folder, such as `app/`, remove it yourself.
`subpath` starts with `./`, so match that too:

```ts
import { defineStorybookVisOptions } from 'storybook-addon-vis/node'

const options = defineStorybookVisOptions({
	visProjects: [
		{
			snapshotRootDir: '__vis__',
			snapshotSubpath: ({ subpath }) => subpath.replace(/^app\//, ''),
		},
	],
})
```

### Organize snapshots across multiple projects

```ts
import { defineStorybookVisOptions } from 'storybook-addon-vis/node'

const options = defineStorybookVisOptions({
	visProjects: [
		{
			snapshotRootDir: '__vis__/components',
			snapshotSubpath: ({ subpath }) => `components/${subpath}`,
		},
		{
			snapshotRootDir: '__vis__/pages',
			snapshotSubpath: ({ subpath }) => `pages/${subpath}`,
		},
	],
})
```

### Use the default configuration

Provide an empty project configuration to use the default snapshot root directory and subpath:

```ts
import { defineStorybookVisOptions } from 'storybook-addon-vis/node'

const options = defineStorybookVisOptions({
	visProjects: [{}],
})
```

## Snapshot path structure

The final snapshot path is constructed as:

```txt
<snapshotRootDir>/<__baselines__|__results__|__diffs__>/<snapshotSubpath>/<task-id>-<variant>.png
```

- `snapshotRootDir` is determined by the `snapshotRootDir` option.
- `snapshotSubpath` is the result of the `snapshotSubpath` function, or the default.
- `task-id` is the story name in lowercase, with every character other than a letter or digit replaced by `-`.
- `variant` identifies the specific snapshot variant.
