Set up the Storybook addon

Unverified

The CSF Next setup (definePreview with addonVis({ auto: true }) and no vitest.setup.ts) has no spec in the repository that covers it, so it is ported as written. The first-run baseline notes and the vis.setup() / storybookVis() options are checked against the repository’s specs.

To setup storybook-addon-vis, you need to do the following:

  • Add the storybookVis plugin in Vitest along with the storybookTest plugin.
  • Configure visual testing in vitest.setup.ts and/or .storybook/preview.ts (see Storybook 10.3+ and Vitest project annotations; with CSF Next, prefer preview-only setup as in Basic Setup for CSF Next).
  • Add storybook-addon-vis addon to your Storybook configuration in .storybook/main.ts.
  • Ignore snapshot folders in your .gitignore file.

Also, if you are using TypeScript, you need to add the storybook-addon-vis/matcher type to your tsconfig.json.

Basic Setup

Section titled “Basic Setup”

storybook-addon-vis provides sensible default setup for both Storybook and Vitest. So setting it up is pretty straightforward.

The basic setup will:

  • Use pixelmatch as the diffing algorithm.
  • Set config to compare image snapshot with a failure threshold of 0 pixels.
  • Timeout for image comparison is set to 30000 ms.
  • Local (non-CI) image snapshots are saved in the <root>/__vis__/local directory.
  • CI image snapshots are saved in the <root>/__vis__/<process.platform> directory.
  • Baseline images are saved in the <root>/__vis__/*/__baselines__ directory.
  • Image snapshots of the current test run are saved in the <root>/__vis__/*/__results__ directory.
  • Diff images are saved in the <root>/__vis__/*/__diffs__ directory.
  • You can review the baseline and diff images in addon Vis panel.

This setup assumes that you are writing your stories in CSF 3. If you are writing your stories in CSF Next, check out Basic Setup for CSF Next.

For Vitest, you need to do two things:

  • Add the storybookVis plugin in vitest.config.ts.
  • Enable visual testing in vitest.setup.ts.

Storybook 10.3+ and Vitest project annotations

Section titled “Storybook 10.3+ and Vitest project annotations”

Unverified

This section has no spec in the repository and is ported as written.

From Storybook 10.3 onward, @storybook/addon-vitest often injects project annotations for you (for example via setProjectAnnotations(getProjectAnnotations())), so you may not need a hand-maintained vitest.setup.ts in every project. See the Storybook Vitest integration docs for the current recommendation.

If you are not using CSF Next (or have not moved your preview config to definePreview), you may still need to adjust your setup: do not rely only on merging visAnnotations inside setProjectAnnotations([...]) in vitest.setup.ts. Put the same lifecycle hooks in .storybook/preview.ts instead, so getProjectAnnotations() includes them when the Vitest addon builds annotations from your preview stack.

You can do that in either of these ways:

  1. Recommended: use definePreview({ addons: [addonVis({ auto: true })] }) in preview.ts even while your stories stay CSF 3—the pattern is the same as in Basic Setup for CSF Next.
  2. Minimal migration: import visAnnotations from storybook-addon-vis/vitest-setup and spread them into a classic preview export, for example export default { ...visAnnotations, tags: ['snapshot'] }, if you are not ready for definePreview.

You may still need vis.setup() and the storybookVis() Vitest plugin depending on your project; this note is only about where visAnnotations is merged (preview vs Vitest setup).

First-run baselines (createMissingBaseline vs updateSnapshot)

Section titled “First-run baselines (createMissingBaseline vs updateSnapshot)”

In vitest-plugin-vis (and when using the same client APIs outside Storybook’s Vitest bridge), createMissingBaseline: true on toMatchImageSnapshot / page.toMatchImageSnapshot, or vis.setup({ createMissingBaseline: true, ... }), can create a missing baseline without passing -u.

When running Storybook + Vitest browser mode through this addon, matcher options are serialized over RPC; custom fields such as createMissingBaseline may not reach the server. In that setup, use Vitest’s snapshot update mode instead (for example temporarily set server.config.snapshotOptions.updateSnapshot = 'all' around the first run, or run with -u) to write new baselines—the same mechanism as a normal snapshot update.
