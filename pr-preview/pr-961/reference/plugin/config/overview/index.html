Customizing the snapshot path

Section titled “Customizing the snapshot path”

Say you have this test:

By default, when you run the test locally, the image snapshot is saved in the following path:

This path breaks down into a few parts.

__vis__/local: snapshotRootDir

Section titled “__vis__/local: snapshotRootDir”

This is the snapshotRootDir where the image snapshot folders are placed. When running on CI, the snapshotRootDir defaults to __vis__/<process.platform>.

__baselines__: baseline folder

Section titled “__baselines__: baseline folder”

This is the folder where the baseline images are saved and used for comparison. There is also a __results__ folder where the images of the current test run are saved, and a __diffs__ folder where the diff images are saved if the comparison fails.

components/MyComponent.spec.tsx: snapshotSubpath

Section titled “components/MyComponent.spec.tsx: snapshotSubpath”

This part is based on the path of the test file relative to the project root. By default, the plugin trims a common folder such as src or test from the path to reduce the path length. See trimCommonFolder.

If you place test files in multiple folders, such as both tests and src, and they might have files with the same name and create conflicting snapshots, use snapshotSubpath to customize the snapshot sub-path to avoid conflicts.

MyComponent/className/can-customize-className: snapshotId

Section titled “MyComponent/className/can-customize-className: snapshotId”

This is the ID of the snapshot, based on the test name and scope. It is not customizable.

auto: snapshotKey

Section titled “auto: snapshotKey”

This is the key of the snapshot. Here it is auto because the snapshot is taken automatically at the end of the test. If you take a manual snapshot, the key is 0, 1, and so on. If you customize the key when taking the snapshot, the global customization is not used.
