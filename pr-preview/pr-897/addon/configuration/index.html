Configure the Storybook addon

To setup storybook-addon-vis, you need to do the following:

  • Add the storybookVis plugin in Vitest along with the storybookTest plugin.
  • Configure visual testing in vitest.setup.ts and/or .storybook/preview.ts (see Storybook 10.3+ and Vitest project annotations; with CSF Next, prefer preview-only setup as in the CSF Next guide).
  • Add storybook-addon-vis addon to your Storybook configuration in .storybook/main.ts.
  • Ignore snapshot folders in your .gitignore file.

Also, if you are using TypeScript, you need to add the storybook-addon-vis/matcher type to your tsconfig.json.

To see working setups, open the published Storybooks and the testcases they are built from. For example, the CSF Next Storybook is built from sb-csf-next.

Basic Setup

Section titled “Basic Setup”

storybook-addon-vis provides sensible default setup for both Storybook and Vitest. So setting it up is pretty straightforward.

The basic setup will:

  • Use pixelmatch as the diffing algorithm.
  • Set config to compare image snapshot with a failure threshold of 0 pixels.
  • Timeout for image comparison is set to 30000 ms.
  • Local (non-CI) image snapshots are saved in the <root>/__vis__/local directory.
  • CI image snapshots are saved in the <root>/__vis__/<process.platform> directory.
  • Baseline images are saved in the <root>/__vis__/*/__baselines__ directory.
  • Image snapshots of the current test run are saved in the <root>/__vis__/*/__results__ directory.
  • Diff images are saved in the <root>/__vis__/*/__diffs__ directory.
  • You can review snapshots in the addon Vis panel. For a failed snapshot, compare the baseline with the result side by side, with a swipe divider, or as an onion skin, or view the diff image.

This setup assumes that you are writing your stories in CSF 3. If you are writing your stories in CSF Next, follow the CSF Next guide.

For Vitest, you need to do two things:

  • Add the storybookVis plugin in vitest.config.ts.
  • Enable visual testing in vitest.setup.ts.

Storybook 10.3+ and Vitest project annotations

Section titled “Storybook 10.3+ and Vitest project annotations”

From Storybook 10.3 onward, @storybook/addon-vitest adds a setup file to your Vitest project that calls setProjectAnnotations(getProjectAnnotations()). getProjectAnnotations() returns the annotations of your .storybook/preview.ts, so you do not need a hand-maintained vitest.setup.ts for them.

The addon skips this step when a setup file in your Storybook config folder (.storybook) contains the text setProjectAnnotations. It prints an info message when it does.

With the visAnnotations from storybook-addon-vis/vitest-setup, you have two ways to set up visual testing:

  1. Preview: merge visAnnotations into .storybook/preview.ts, as shown below. Keep only vis.setup() in vitest.setup.ts.
  2. Vitest setup: merge visAnnotations in setProjectAnnotations([...]) in vitest.setup.ts, as in Basic Setup. Because that file calls setProjectAnnotations, Storybook does not provision the preview annotations for you.

If you use CSF Next, use definePreview({ addons: [addonVis({ auto: true })] }) instead. It carries visAnnotations already. See the CSF Next guide.

The testcase sb-csf-3 uses exactly this setup. The other testcases, for example sb-csf-mix, use the Vitest setup way.

Advanced Setup

Section titled “Advanced Setup”

If you need more control over the visual testing, you can customize the addon configuration.

In vitest.config.ts, you can customize where the snapshots are saved and how they are compared.

The options are the same as the options in vitest-plugin-vis minus the preset.

For more details, please refer to the vitest-plugin-vis documentation.

In vitest.setup.ts, you can customize how the automatic snapshots are taken.

For several Vitest projects or custom snapshot paths, see Monorepos and custom snapshot paths. To create the first baselines, see Get started.
