expect().toMatchImageSnapshot()

expect().toMatchImageSnapshot() is a custom matcher that compares the subject to a baseline image snapshot. It is also available on the global expect.

It can be used whether or not you enabled the auto preset. Typically you disable auto snapshots when you take snapshots manually.

Disable auto snapshots

Section titled “Disable auto snapshots”

You can disable auto snapshots at various levels:

See setAutoSnapshotOptions. A manual snapshot can be taken together with an auto snapshot in the same test. The manual snapshot gets the key 1.

Basic usage

Section titled “Basic usage”

Subject

Section titled “Subject”

The subject can be:

  • a Locator, for example page.getByTestId('subject')
  • an element, for example page.getByTestId('subject').element()
  • document.body, or the baseElement returned by render() (same as the body)
  • an image encoded as a base64 string

Anything else fails immediately. A string that is not base64 encoded fails with:

The same message is used for undefined, null, true, false, and numbers.

Options

Section titled “Options”

The matcher accepts an optional options object.

snapshotKey

Section titled “snapshotKey”

Customize the snapshot key.

A key that contains a dash is rejected with Snapshot key cannot contain dash.

createMissingBaseline

Section titled “createMissingBaseline”

When true and there is no baseline image yet, the matcher writes the captured image as the baseline and the assertion succeeds, without using Vitest’s -u (updateSnapshot) mode. If a baseline already exists, it does not change the comparison.

You can set a default for auto snapshots with vis.setup({ createMissingBaseline: true, auto: ... }). setAutoSnapshotOptions({ createMissingBaseline }) in a test overrides that default.

animations

Section titled “animations”

'disabled' finishes finite CSS animations and transitions and cancels infinite ones before the snapshot is taken, so an animated component gives a stable image. 'allow' leaves them running. The default is 'allow'. It works with the Playwright and WebdriverIO providers, because the matcher settles the animations in the page before it asks the provider for the screenshot.

You can set a default for auto snapshots with vis.setup({ animations: 'disabled', auto: ... }). setAutoSnapshotOptions({ animations }) in a test overrides that default.

failureThreshold and failureThresholdType

Section titled “failureThreshold and failureThresholdType”

Control how much difference is allowed before the test fails. failureThresholdType is 'pixel' (the default) or 'percent'. With 'percent', the threshold is a percentage from 0 to 100: 1 allows 1% of the pixels to differ.

When the difference is beyond the threshold, the error message says how far:

With no threshold the message is Expected image to match but was differ by N pixels. (for percent, ... but was differ by N.NN%.). N stands for the measured difference.

comparisonMethod

Section titled “comparisonMethod”

'pixel' (the default) compares pixel by pixel. 'ssim' compares structural similarity.

With ssim, a threshold in pixels works the same way, for example failureThreshold: 20 fails with Expected image to match within 20 pixels but was differ by N pixels.

diffOptions

Section titled “diffOptions”

The options are passed to the comparison library, so the defaults are those of the library. For comparisonMethod: 'pixel', the options of pixelmatch:

For comparisonMethod: 'ssim', the options of ssim.js. Unless you set ssim, the plugin uses 'bezkrovny':

timeout

Section titled “timeout”

Set a timeout for taking the snapshot, in milliseconds. The default is 30000.

reviewImage

Section titled “reviewImage”

When a snapshot mismatches, the matcher writes <name>.regions.json and <name>.review.png next to the diff image. Set reviewImage: false to not write the review image. The regions file is still written.

For the files, the failure message and the cases where the review image is skipped, see Reviewing failures.

mask

Section titled “mask”

Paint regions over before the snapshot is taken, so content that changes on every run does not fail the comparison. Each entry is a CSS selector, a locator, or an element. Every match is masked, and entries that match nothing are ignored.

maskColor is any CSS color. The default is #FF00FF. Playwright paints the regions with its own mask option. WebdriverIO has no such option, so the plugin adds overlay boxes on top of each match, takes the screenshot, and removes them. You can also set mask with setAutoSnapshotOptions() and vis.setup({ auto }).

expectToFail

Section titled “expectToFail”

Expect the matcher to fail. It is useful for testing that changes are detected.

The failure message includes the paths of the images:

If the snapshot matches although expectToFail is set, the matcher fails with Snapshot ... matched but expected to fail, followed by the options used, the diff, and the image paths.

If the image size changed, the message is Snapshot ... mismatched followed by The image size changed from 128x128 to 64x64 (the sizes are the baseline and the result), and the review image is skipped.

Errors

Section titled “Errors”
  • Called outside a test: '`toMatchImageSnapshot()` must be called in a test.'
  • Called in a concurrent test: '`toMatchImageSnapshot()` cannot be called in a concurrent test because concurrent tests run at the same time in the same iframe and affect each other's environment.'
  • Snapshot key with a dash: Snapshot key cannot contain dash.

Retry

Section titled “Retry”

The matcher supports Vitest’s retry option. A test with { retry: 1 } can take more than one snapshot with different content.
