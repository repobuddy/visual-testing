Reviewing failures with agents

When an image snapshot fails, a coding agent often opens the baseline and the result and compares them. Images are the most expensive input an agent reads. This page shows what each view costs and the order in which an agent should look.

In short: read the error message, then open the review image instead of the full images. When the message says the review image is not cropped, open the Actual or Difference image instead: they cost less.

What a failure gives you

Section titled “What a failure gives you”

A failed toMatchImageSnapshot throws a message like this:

When the two images have different sizes, the message also says The image size changed from 1280x720 to 333x720.

The message is text and costs little. It tells the agent how much changed, whether the layout changed size, where each changed region is, and where the images are.

The Changed: line lists each changed region as <width>x<height> at (<x>,<y>). The plugin finds the changed pixels, grows them by 16 px, and turns each connected area into one region. Anti-aliasing differences are not counted.

The review image places, for each region, the Expected crop, the Actual crop, and a diff crop next to each other. The diff crop shows the baseline in gray at full contrast with the changed pixels in red, so small text in the changed area stays readable.

Cropping does not help when the image size changed, there are more than 5 regions, the regions cover more than half of the image, or no region is found. The review image then places the whole Expected, Actual, and diff side by side, and the Review: line says why:

The whole-image review is for a person browsing the __diffs__ folder. It holds three full images, so an agent spends fewer tokens on the Actual or Difference image alone. reviewImage: 'full' writes the whole-image review for every failure.

The regions are also written next to the diff, as primary.regions.json: { "width": 1280, "height": 720, "regions": [{ "x": 0, "y": 0, "width": 106, "height": 37 }] }. Tools and UIs read this file to zoom to the changes; an agent gets the same data from the Changed: line.

The Difference image is made by pixelmatch with its default colors:

  • red pixels are pixels that changed.
  • yellow pixels are anti-aliasing differences. They do not count toward the failure.
  • gray is the baseline, faded, for context.

The faded baseline makes small text hard to read in the Difference image. It shows where the change is, not always what it is.

What each view costs

Section titled “What each view costs”

Claude reads an image in 28 × 28 pixel patches, and each patch is one token: ⌈width / 28⌉ × ⌈height / 28⌉, after the image is scaled down to fit the model’s limit (2576 px on the long edge and 4784 tokens on current models). See Vision in the Claude docs. Other models count image tokens differently, but most charge more for larger images.

For the 1280 × 720 page above, where a 106 × 37 area changed:

What the agent opensImage tokens
Expected and Actual2,392
Difference only1,196
Review image (106 × 119)20

The Difference image is the same size as each snapshot, so it always costs half of the pair. The review image holds only the changed region, three times, so its cost follows the size of the change, not of the page.

Across 112 failing comparisons from this repository, measured on 2026-11-03 (see How this was measured). The numbers are a dated measurement, not a guarantee. They change as the repository’s baselines change:

What the agent opensFull pages (57)Components (51)Size changed (4)
Expected and Actual75,07235,7086,032
Difference only37,536 (2.0× less)17,854 (2.0× less)4,784 (1.3× less)

Three things stand out:

  • The plugin wrote a cropped review image for 100 of the 112 comparisons: 56 of the 57 full pages and 44 of the 51 components. The median one costs about 10 tokens and the largest costs 217.
  • It did not crop 1 full page and 7 components. Four of the components are 86 × 36 images where the change covers 84%, and the Difference image costs 8 tokens each. The other three components and the full page have 6 to 8 regions, more than the limit of 5, and the Difference image costs between 208 and 962 tokens each.
  • It did not crop all 4 size changes. The Difference image is padded to the larger image and most of it shows the padding, so the agent opens only the Actual image. The cost depends on which image is the larger one: 312 tokens when the result shrank to 333 × 720, and 1,196 when it grew to 1280 × 720.

What the agent should do

Section titled “What the agent should do”

1. Read the error message first. It gives the pixel count, any size change, the changed regions, and the image paths.

2. Open the review image. For each region, it shows Expected, Actual, and the changed pixels in red, side by side. Do not open the full Expected, Actual, or Difference images unless the review image leaves the question open.

3. If the message says the review image is not cropped, read why, and open one full image instead.

  • The image size changed: open only the Actual image. A size change means the layout changed, and the Actual image shows the new layout.
  • Too many regions, or the regions cover most of the image: open the Difference image. Note where the red pixels are, then open Expected and Actual only if the Difference image does not show what changed.

4. If there is no Review: line, the review image is turned off (reviewImage: false). The Changed: line still gives each region. Crop Expected and Actual to those regions with any image tool the environment has, and open the crops, for example magick primary.png -crop 106x37+0+0 +repage primary.crop.png.

5. Decide what the change is. Update the baseline (run the tests with -u) only when the change is what the task intended. If the content is the same and only the edges of text or shapes differ, it is rendering drift (fonts, operating system, browser). Report it instead of updating the baseline. Anything else is a regression to fix or report.

Turning the review image off

Section titled “Turning the review image off”

The review image is on by default. Set reviewImage: false in vis() or in a toMatchImageSnapshot() call to not write it. The regions file and the Changed: line are still written.

How this was measured

Section titled “How this was measured”

The image pairs come from this repository’s committed baselines:

  • 118 tests that have both a linux and a win32 baseline. The Linux image is the baseline and the Windows image is the result. 110 of them differ, mostly in how text is rendered.
  • 2 baselines that a commit changed in place, where the image size changed.

The groups in the table are: size changed, when the two images differ in size; full pages, 1280 px wide; and components, everything else.

For each pair, the script pads both images to the same size, as this plugin does, and runs the plugin’s own code to compare them with default options, find the changed regions, decide whether to crop the review image, and build the cropped one. It then computes the token cost of each view with the formula above. The 8 identical pairs are left out.

The figures above come from running it on 2026-11-03, at commit 3ce4e48e, with Node 26. To reproduce, run from the repository root after pnpm install:

It writes results.json and every image it measured, with the review images and region files, to <out-dir>. See scripts/measure_diff_tokens.mjs.

Limits of this measurement:

  • The token counts are computed from Anthropic’s published formula, not read from API usage.
  • It measures cost, not whether the agent reaches the right decision from each view.
  • Most of the changes are small text-rendering differences, and every comparison has one changed region. A change that spreads across a page gives a larger review image, or an uncropped one.
