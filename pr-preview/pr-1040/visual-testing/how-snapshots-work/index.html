How snapshots work

This page applies to both packages. storybook-addon-vis runs vitest-plugin-vis, so they write the same files.

Three images

Section titled “Three images”

A snapshot has up to three images:

  • Baseline. The accepted image. You commit it.
  • Result. The image the current run captured. It is written to disk and not committed.
  • Diff. Written only when the result does not match the baseline. It shows the changed pixels in red.

A failed comparison writes two more files next to the diff: <name>.regions.json with the changed regions, and <name>.review.png that crops each region, or shows the whole images when cropping does not help. Reviewing failures explains both.

If the baseline and the result have different sizes, the comparison first resizes both to the larger size, then compares them.

Folder layout

Section titled “Folder layout”

By default the images go under __vis__ in the project root:

<platform> is local when you run on your machine. In a CI environment, detected with is-ci, it is the value of process.platform, for example linux or win32. Platforms and CI explains why.

The <test file> folder is the path of the test file relative to the project root. By default a leading src, test, tests, source, js, ts or lib folder is dropped. The snapshotRootDir and snapshotSubpath options change the root and the sub-path. trimCommonFolder describes the trimming.

Automatic snapshots are named auto, and a theme adds its name, for example primary-dark.png. A manual snapshot takes its name from the test or from snapshotKey.

Where the names come from

Section titled “Where the names come from”

The folder names are exported as constants from vitest-plugin-vis/server-utils: SNAPSHOT_ROOT_DIR, BASELINE_DIR, RESULT_DIR, DIFF_DIR, REVIEW_IMAGE_SUFFIX and CHANGED_REGIONS_SUFFIX.
